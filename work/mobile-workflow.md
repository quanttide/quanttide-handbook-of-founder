# 移动端工作流

## 场景

不在电脑前时，执行仍然要落在电脑上：手机负责下指令、查收和评审，电脑负责跑任务，GitHub 作为两端之间的交换层。

## 分工

| 端 | 承担 | 工具 |
|----|------|------|
| 手机 | 派任务、查收结果、评审解读 | Hermes、Working Copy、官网 App |
| 电脑 | 执行任务、提交产物 | Hermes 连接端 |
| GitHub | 交换产物与上下文 | 仓库分支与提交 |

## 操作

1. 手机打开 Hermes，连接电脑，把任务说清楚：目标、仓库与分支、交付物、合格线。
2. 电脑执行，产物提交并推送到 GitHub。
3. 手机用 Working Copy 拉取仓库，查收分支、提交与产物，确认这一轮交付是否齐全。
4. 把查收结果交给手机官网 App，让它评审与解读：哪些达成、哪些偏离、下一步做什么。
5. 评审结论回到 Hermes，成为下一轮任务；有长期价值的写进手册或档案。

## 要点

- 结果必须落到仓库，写清分支、提交和产物路径；只留在对话里的结果，手机上查收不到。
- 手机只做判断，不在手机上改代码；改动一律回电脑执行。
- 评审结论要回流成任务，否则流程断在评审这一步。
