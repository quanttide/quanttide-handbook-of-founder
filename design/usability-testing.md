# 可用性实测

## 判断

可用性判定只认实测输出，不认设计意图与代码推断。要判定「环境错误是否被伪装成空结果」，或要给一个界面打分时，按下面做。

UI 与 UX 的实测方式不同——**截图能判的是 UI，必须操作一遍才能判的是 UX**，两面取证分开做，不互相替代。

## 做法

**UX 侧（走一遍）**

1. **注入环境错误**：把根路径指到不存在的目录、去掉显示环境或降低权限，取输出 A（记 stdout 原文与 exit code）。
2. **取真空数据**：同一命令，数据根换成空目录，取输出 B。
3. **比对**：stdout 与 exit code 任一不同即区分成功；全同即失败，判为「环境错误被伪装成空结果」。
4. **走完整条路**：从打开到拿到结果记步数；每条结果试着回一次源头（路径、日期）；故意走错一次，看有没有恢复路径。

**UI 侧（看物件）**

5. **四态各截一张**：空、加载、错误、成功，缺哪态记哪态。
6. **核文本**：把用户可见文本全部读一遍，挑出实现术语（编译开关、内部字段名、依赖名）。
7. **核访问**：键盘走一遍主流程；确认中文渲染与缩放；同一概念核对是不是只有一个名字。

**记分**

8. **未验的标出来**：整维没测的不参与加权，另标覆盖率；维内只测了一部分的，得分只反映已测部分，未测部分列为「待验」，不按代码推断给分。

## 边界

- **不用解释兜底**：测不出区分就判不过，不因为「设计上是想区分的」而放行。
- **不把配置错误当空结果**：两者输出相同的那一刻，问题在实现，不在用户。
- **不测没有输出的环节**：判定对象必须是可观察的输出（stdout、exit code、窗口表现）。
- **两面不互相顶替**：UX 走通不能补 UI 缺态，UI 截图不能证明 UX 闭环。
