# 智能体协作

## 定位

本篇归纳智能体协作的一般规律，用于判断任务如何分配、交接与验收。具体入口与操作步骤不在本篇范围。

## 关系结构

协作关系由三个主体与两个载体构成。

主体是判断方、编排方与执行方。判断方由人担任，负责定义任务、验收结果与决定回流；编排方负责转发任务、维护状态；执行方负责产出交付物。判断方与执行方不得合并。编排方仅在任务需要跨入口转发时设立，可由人或智能体承担。

载体是对话与仓库。对话传递指令与中间判断，仓库保存任务状态、交付物与提交记录。两者不互为备份：对话中的结果不构成交付，仓库中的产物不替代任务协商。

## 基本规律

1. 判断与执行分离。执行可以委派，判断与验收不可委派。
2. 角色不绑定工具。同一角色可由不同工具承担，工具更换不改变职责边界。
3. 仓库是唯一交换层。交付物、任务状态与提交记录必须落到仓库，并写明分支与产物路径。
4. 一个入口一个职责。同类任务固定使用同一入口，入口按职责选择。
5. 交接契约化。派单写明对象、任务、交付、合格线与验收人，接收方不依赖对话上下文即可执行。
6. 异步闭环。流程按派单、执行、查收、评审、回流运行，不依赖发起方在线。
7. 结论必须回流。评审结论转为下一轮任务或写入规则；未回流的评审不产生协作收益。

## 人的职责

人的职责限定为澄清目标、派单、验收与回流。执行、转发与状态记录由智能体或仓库承担。

## 失效条件

- 交付物只留在对话中，接收方无法查收。
- 同类任务在多个入口之间切换，上下文需要重复搬运。
- 派单缺少合格线或验收人，执行结果无法判定。
- 评审结束即终止，没有下一轮任务。
- 转发层级过长，失败位置无法定位。
