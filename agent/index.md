# 智能体协作

协作的两方是 owner 与 reviewer：owner 执行并持有仓库，reviewer 评审并维护规则。两方不得合并。

两方的连接方式分两种：直连与转发，差别在于两方之间是否另有转发方居中。

直连结构最扁平，也是理想模式：两方之间只有仓库。owner 把产物提交进仓库，reviewer 直接从仓库查收，对照产物本身做判断。移动端工作流属于这种——电脑端执行并推送，手机端拉取仓库、查收产物、做出评审，评审结论再人工转成下一轮任务。代价是人工操作多，从查收到结论回流全靠手工衔接。

转发省人工，但多一层：reviewer 与 owner 之间另有转发方居中。reviewer 把派单交给转发方，转发方转给 owner 执行，结果沿原路回传，reviewer 据此验收。后台派单属于这种——Hermes 转发，Pi 执行，人验收。派单与回传都经过中间方，失败定位也要人工排查；判断建立在转述上，结构上不如直连理想。

两种方式的取舍恒定：转发每省一分人工，判断就多经一道转述。转发方只传消息，不代做判断；验收始终由 reviewer 直接做出。

仓库是两方唯一的交接点；对话只传指令，不存结果。无论直连还是转发，产物先进仓库，评审才成立。
