# 智能体协作

## 适用范围

适用于三类任务：需要在电脑端多个入口之间分工的任务、人不在电脑前仍需推进的任务、不留在当前对话中而交由后台执行的任务。

## 分工

- Hermes 转发任务，Pi 执行任务，人验收结果。
- 手机端提出任务、查收结果并评审，电脑端执行并提交产物。
- Zed 承担深度编辑，Pi 承担项目交互，Hermes desktop 承担跨仓库整理。
- OpenCode 与 dsh 仅作补充入口，不承担主路径任务。

职责按分工划分，不按工具功能划分；同一职责可以由不同工具承担。

## 操作

1. 写清对象、任务、交付与合格线，四项缺一不可。
2. 写清仓库、分支与产物路径，确保执行结果可定位。
3. 指定验收人。验收权由人保留，不转交智能体。
4. 提交任务后由后台执行，流程不依赖当前对话继续。
5. 执行结束后回收交付物，运行测试，逐项核对合格线。
6. 将评审结论转为下一轮任务；长期有效的结论写入手册或档案。

## 要点

- 仓库是唯一交换层。对话只传递指令，不作为结果存放位置。
- 同一类任务固定使用同一入口，避免在入口之间搬运上下文。
- 执行可以委派，判断与验收不可委派。
- 代码修改只在电脑端进行，手机端只提交指令与评审意见。

## 限制

- 各入口没有统一状态视图，谁在执行、卡在哪、下一轮是什么需人工记录。派单时同步记录任务状态。
- Hermes 到 Pi 为两级转发，失败定位需人工排查。派单时写明失败回传方式。
- 手机端评审结论不自动回流。评审结束后须手工转成下一轮任务。
